Ratchet — deployment gate service

A service that holds a lock on each environment and only opens it when every required check has actually reported green.

Our deploy pipeline let engineers approve a release before the slower integration suite had finished, so a red build could reach production and nobody noticed until the error rate moved. Ratchet inverts that: the deploy blocks on a lease, and the lease is only granted when the checks report in. The interesting part was making it fail open safely — if Ratchet itself is down, deploys must not stop, so leases carry a TTL and the client degrades to a warning after 30 seconds. Bad-deploy rollbacks went from roughly three a month to none in the six months since.

Ledger reconciliation tooling

A daily job that compares our internal ledger against the provider's settlement file and explains every difference.

Finance were reconciling by hand in a spreadsheet, which took two days a month and found breaks a week after they happened. The hard part was not the diff — it was that the two systems disagree legitimately for about 14 hours around a settlement window, so a naive comparison is all false positives. I modelled the expected lag per payment method and only flag a break once it has survived its window. It now runs in four minutes and finds real breaks the same morning.

pgslice — schema migration linter

A pre-commit hook that catches Postgres migrations which will take a lock long enough to cause an outage.

Written after I personally took a service down by adding a NOT NULL column to a 40-million-row table. It parses the migration, works out which lock each statement takes and for how long, and refuses anything holding an ACCESS EXCLUSIVE lock on a large table without an explicit override comment. About 200 lines of real logic and a lot of test cases pulled from Postgres' own lock documentation.
